启动说明 Guide

双工程（server / client）+ 共享契约（shared）。本页给出最短可跑路径：准备环境、启动服务端并监控、启动客户端登录，以及自检与 CI。

开始启动 启动客户端 常见问题

快速开始

三步跑起来。所有命令在仓库根目录执行，默认端口 7000。

Step 1

准备环境

设置 $env:GODOT，联接 shared，导入两个工程（首次必须）。

Step 2

启动服务端

scripts/start_server.ps1 一键启动并监控状态。

Step 3

启动客户端

scripts/start_client.ps1 拉起窗口并自动登录。

# 1. 准备环境（首次/每个新 worktree）
$env:GODOT = "D:\code\game\godot_engine\Godot_v4.7.1-stable_win64_console.exe"
powershell -File scripts/link_shared.ps1
& $env:GODOT --headless --path server --import
& $env:GODOT --headless --path client --import

# 2. 启动服务端（后台 + 状态可查）
powershell -File scripts/start_server.ps1

# 3. 启动客户端并自动登录（新账号用 -Register）
powershell -File scripts/start_client.ps1 -User alice -Password secret1 -Character Hero -Register

图形化启动器

不想记命令就用 WinForms 启动器：所有配置都在界面里改，点“保存配置”写入 .local/launcher.json，下次自动载入。

# 打开图形化启动器（配置 + 启动/停止服务端与客户端）
powershell -File scripts/launcher.ps1

# 无需弹窗的自检 / 冒烟测试（供 CI、agent 使用）
powershell -File scripts/launcher.ps1 -SelfTest
powershell -File scripts/launcher.ps1 -SmokeTest

# 打包成 exe（双击运行，无需命令行）
powershell -File scripts/build_launcher_exe.ps1
# -> build/MMORPG-Launcher.exe（约 5KB，放在仓库内即可）
配置可视化

不再传参数

引擎路径、端口、数据库、--no-mobs/--aoi-stats、登录账号/密码/角色、窗口数量都在表单里；保存为 .local/launcher.json（gitignore）。

一键启停

服务端 + 客户端

“启动/停止服务端”“启动客户端”“停止客户端”按钮，内部复用 start_server.ps1 / start_client.ps1，行为一致。

可打包 exe

双击即用

build_launcher_exe.ps1 编译出 build/MMORPG-Launcher.exe 原生包装器：无控制台窗口，转发参数并透传退出码。

状态监控

自动刷新

每 2 秒刷新服务端 PID 与日志尾部；也可点“刷新状态”。“打开启动说明”直达本页。

依赖 Windows PowerShell 5.1 + .NET WinForms（Windows 自带）。脚本源码为 UTF-8 带 BOM，否则中文界面会乱码。

环境准备

引擎、导出模板、godot-sqlite 三者版本必须一致，错配会静默破坏导出或插件加载。

引擎

Godot 4.7.1-stable

未加入 PATH；脚本只读 $env:GODOT，不要把绝对路径写进被提交的脚本。

插件

godot-sqlite v4.9

compatibility_minimum = "4.7"；server/addons/godot-sqlite/ 必须提交（约 300MB）。

共享契约

shared 目录联接

link_shared.ps1 幂等创建 client/shared、server/shared；每个 worktree 都要重跑。

# 校验引擎版本
& $env:GODOT --version
# -> 4.7.1.stable.official.a13da4feb

# 联接共享契约 + 门禁校验（RPC 契约对账）
powershell -File scripts/link_shared.ps1 -Verify
解析检查（没有独立 lint/typecheck，headless 启动即报解析错误）：
& $env:GODOT --headless --path server --quit-after 3 -- --server
& $env:GODOT --headless --path client --quit-after 5

服务端

推荐用启动工具：它把服务端放到后台运行，并记录 PID 与日志，方便随时查看状态。

# 启动（默认 127.0.0.1:7000，DB=.local/mmorpg_server.db）
powershell -File scripts/start_server.ps1

# 监控：RUNNING/STOPPED + 最后 ready 行 + 日志尾部（-Follow 每 5s 刷新）
powershell -File scripts/start_server.ps1 -Action status -Follow

# 其它动作
powershell -File scripts/start_server.ps1 -Action logs
powershell -File scripts/start_server.ps1 -Action restart -NoMobs
powershell -File scripts/start_server.ps1 -Action stop

工具参数

参数说明
-Actionstart / stop / restart / status / logs
-PortUDP 端口，默认 7000
-DatabaseSQLite 路径（相对路径按 项目目录 解析）
-NoMobs / -AoiStats透传 --no-mobs / --aoi-stats
-Follow / -Intervalstatus 的循环监控模式

手动启动（等价）

& $env:GODOT --headless --path server -- --server --port 7000 --db .local/mmorpg_server.db

# 看到这行才算起来：
# [server] listening on UDP 7000 (max 16 clients, tick 20Hz)
PID 与日志位于 server/.local/：server.pid、server.out.log、server.err.log。该目录与数据库一样被 gitignore。

客户端

启动工具会拉起 GUI 窗口（无额外控制台），可自动填账号、登录，甚至创建/选择角色并进入世界。

# 自动登录；带 -Character 会建/选该角色并进入世界
powershell -File scripts/start_client.ps1 -User alice -Password secret1 -Character Hero -Register

# 只登录到角色选择界面（省去 -Character）
powershell -File scripts/start_client.ps1 -User alice -Password secret1

# 一次开两个窗口（用户名/角色名自动加 1、2 后缀）
powershell -File scripts/start_client.ps1 -User alice -Password secret1 -Character Hero -Register -Count 2

# 关闭上次启动的窗口
powershell -File scripts/start_client.ps1 -Action stop

工具参数

参数说明
-User / -Password账号；只给 -User 时预填用户名、密码手输
-Character角色名；省略则停在角色选择界面
-Register注册新账号（而不是登录）
-Count窗口数量，默认 1
-ServerHost / -Port目标地址，默认 127.0.0.1:7000

手动启动（等价）

# GUI 版引擎（少一个控制台窗口）
& 'D:\code\game\godot_engine\Godot_v4.7.1-stable_win64.exe' --path client -- --host 127.0.0.1 --port 7000

操作键位

  • WASD 移动  ·  鼠标 转视角  ·  左键 / 空格 / 1 攻击
  • Tab 选择最近怪物  ·  Esc 释放鼠标
两个窗口要用 不同账号，才能互相看到对方；客户端只发输入/意图，位置以服务端为准（本地预测仅为手感）。

自检与 CI

无头 bot 是客户端唯一的自动化验证手段；单元测试与 CI 保证重构不回归。

# 无头 bot 自检（退出码 0 = 全通过；端口需与服务端一致）
& $env:GODOT --headless --path client -- --bot --host 127.0.0.1 --port 7000

# 必须并发两个 bot 才能测“看到另一名玩家移动”
& $env:GODOT --headless --path client -- --bot --port 7000 --bot-user a --bot-require-peer
& $env:GODOT --headless --path client -- --bot --port 7000 --bot-user b --bot-require-peer

# 单元测试（必须用仓库绝对路径，相对路径会解析成 res://tests/... 而失败）
& $env:GODOT --headless --path server --script "\tests\run_tests.gd"

# 一键 CI：Verify -> 解析 -> 单测 -> bot -> 导出（Linux 服务端 + Windows 客户端）
powershell -File scripts/ci.ps1 -Godot $env:GODOT
bot 输出契约

别改格式

[bot] CHECK <name>=OK|FAIL|N/A … [bot] RESULT PASS，退出码 0/1，CI 依赖它。

bot 断言

按域拆分

client/scripts/bot_checks/bot_check_<域>.gd，运行时 glob 自动注册；现有 session / movement / combat / inventory / zones。

区域隔离

opt-in 开关

不带 --zone-check N 时 zones 断言不产出；两个 bot 加 --bot-multiplayer --zone-check 1/2。

常见问题

按经验整理的高频坑，全部在本仓库实测过。

headless 报解析错误 / class_name 未注册

先跑一次 --import（见“环境准备”）。新增脚本后也要重新 import。

单元测试找不到脚本

必须用 仓库绝对路径 --script "<repo-root>\tests\run_tests.gd"；相对路径会解析成 res://tests/…。

-Db 参数直接报错

-Db 与 PowerShell 内置 -Debug 别名冲突；服务端工具的参数名是 -Database。

客户端 -Host 报错

-Host 会撞 PowerShell 内置 $Host；用 -ServerHost。

两个服务端端口冲突

每个 worktree 用独立 --port 与 --db .local/<name>.db；--db 相对路径按项目目录解析（server/.local/…）。

bot 复跑 movement FAIL

怪被反复击杀后会漂到玩家身边，位移不足 1m。换一个干净的 --db .local/<new>.db 重跑。

50+ bot 压测撞上限

Protocol.MAX_CLIENTS=16；压测前需调大该常量或分线。

中文文件在 PowerShell 里乱码

文件是 UTF-8 无 BOM；Get-Content/Select-String 需加 -Encoding UTF8。乱码是控制台问题，别改编码。

系统构成

server/

专用服务器：20Hz 权威世界 + 装配（main.gd）+ 各子系统（world_*）+ 技能/背包/区域。

client/

Windows 客户端：登录/角色 UI、本地预测、插值渲染、无头 bot 自检。

shared/

契约与共享纯函数：协议/RPC、移动结算、战斗公式、数据表、DTO。经目录联接映射进两端。
